# AI 对话模块——失败处理与可靠性后续工作

> **状态：** 后续工作提醒（2026-07-30）
>
> **用途：** 明确记录通用 AI 对话模块第一阶段尚未彻底解决的失败恢复与可靠性问题。
> 本文件不是当前版本已实现能力的声明，也不属于首期验收标准。
>
> **总设计入口：** [AI Chat 通用模块与架构设计](./2026-08-01-ai-chat-functional-boundaries-design.zh-CN.md)
>
> **经历业务设计：** [经历适配器与字段对话设计](./2026-08-01-experience-adapter-design.zh-CN.md)

## 1. 当前结论

首期设计已经提供基础兜底：

- 字段覆盖和模型续跑分事务阶段处理，模型失败不会重复覆盖；
- 审批后立即进行一次无工具续跑；
- 立即续跑失败时静默恢复输入；
- 下一条用户消息在同一次模型调用中补传 Tool Result；
- Tool Result 补传不额外调用模型，也不重新执行字段覆盖；
- 字段级 revision 防止旧提案覆盖已保存的新值；
- client ID 防止重复消息和重复审批。

这些规则可以满足首期正常流程和常见短暂失败，但**当前聊天失败处理仍然不够完善**。
尤其是在进程崩溃、长时间网络中断、多实例部署、供应商异常流和事件投递丢失等情况下，
仍需要更成熟的持久化任务、事件重放和恢复机制。

## 2. P0：进程崩溃与事务后任务恢复

### 2.1 持久化续跑任务

当前审批事务虽然会保存 Tool Result 和续跑意图，但如果进程在事务提交后、模型调用开始前
退出，续跑可能只能等到下一条用户消息触发补传。

后续应评估：

- 建立持久化 job/outbox 表；
- 审批事务中原子写入 continuation job；
- 独立 worker 或恢复扫描器领取任务；
- 使用 lease、防重 ID 和最大尝试次数；
- 进程重启后自动恢复未执行任务；
- 明确何时放弃立即续跑并转为延迟补传。

### 2.2 孤儿运行恢复

需要扫描长期停留在以下状态的记录：

```text
run.running
run.suspended
tool_call.pending
conversation.active 但已过 expires_at
```

为每种状态定义确定的恢复、结束或失效规则，避免数据库永久保留无法继续的假活动状态。

## 3. P0：SSE 可靠投递与事件重放

当前设计保证提案先入库再发事件，但尚未定义完整的持久化事件日志和跨连接重放。

后续需要：

- 为 SSE 事件分配持久化、严格递增的 event ID；
- 支持 `Last-Event-ID` 或等价游标；
- 区分模型已完成但前端未收到，与模型自身失败；
- 同一页面短暂断线后只补发缺失事件；
- 保证 `proposal.requested`、`proposal.resolved` 不重复改变前端状态；
- 评估多进程部署下的 Redis Stream、数据库 outbox 或消息代理；
- 定义事件保存时长和清理策略。

## 4. P0：供应商流式与 Tool Call 兼容性

不同 LLM 供应商对 Tool Call 的流式格式、结束原因、参数分片和错误返回并不完全一致。

后续需要建立供应商契约测试：

- Tool name 与 arguments 分片顺序变化；
- UTF-8 字符跨分片；
- 一个 chunk 包含多个 Tool Call；
- 正文和 Tool Call 交错；
- 缺少 finish reason；
- 参数永远不闭合；
- 供应商返回格式正确但 Schema 不合法；
- 供应商在部分正文后超时；
- 模型在 `tool_choice=none` 时仍返回工具结构；
- 本地模型或兼容 API 不完整支持 Tool Call。

需要确定每种异常的稳定内部错误码、是否允许降级为纯文本，以及哪些情况必须终止运行。

## 5. P1：重试、退避与熔断

首期审批后自动续跑只尝试一次，这是安全的基础策略，但不是完整的可靠性策略。

后续应按错误类型区分：

- 可重试的连接错误、限流和临时 5xx；
- 不可重试的认证、配额、Schema 和业务校验错误；
- 带 `Retry-After` 的供应商响应；
- 指数退避和随机抖动；
- 单供应商熔断；
- 切换备用模型或供应商的条件；
- 用户主动重试与后台自动重试的幂等边界。

任何重试都必须保证：

- 不重复写字段；
- 不重复审批；
- 不重复保存用户消息；
- 不让同一 Tool Result 产生多个并行续跑。

## 6. P1：部分流内容与 UI 恢复

首期对审批后续跑的部分失败内容采用静默移除，但仍需验证不同网络和渲染时序下是否会
出现闪烁、残留或消息顺序错乱。

后续可评估：

- 对自动续跑使用短缓冲后再展示首段文字；
- 失败消息的本地回滚动画；
- 消息 delta 去重；
- 页面后台化、休眠和恢复后的流状态；
- 浏览器取消请求与服务端生成取消的同步；
- 超长回答导致的内存增长；
- 同一消息多个并发订阅者的一致性。

用户主动发起的普通聊天失败是否保留部分回答，也应形成统一产品规则。

## 7. P1：多标签页和外部写入同步

字段级 revision 可以阻止错误覆盖，但另一个标签页修改字段后，当前审批框不会立即知道。

后续可增加：

- BroadcastChannel 或服务端事件同步；
- proposal 因外部更新失效时主动关闭审批；
- 多标签页会话互斥或明确允许并存；
- 当前页面与外部 API 同时保存时的用户提示；
- 全局保存与局部保存跨标签页的冲突合并策略。

## 8. P1：一致性审计与修复

需要提供后台一致性检查，识别理论上不应出现的状态：

- Tool Call 为 `applied`，但字段 revision 未增加；
- Tool Result 缺失或与 Tool 状态冲突；
- 一个 proposal 对应多个 continuation run；
- consumed Tool Result 没有完整后续消息；
- ended 会话仍有 running run；
- pending proposal 关联的经历或字段已经删除；
- 字段 revision 行缺失或低于业务写入次数。

后续应定义只读审计命令、可恢复修复动作和人工确认边界，不能自动猜测业务字段值。

## 9. P1：可观测性与隐私

失败处理成熟前需要可观测，但不能泄露用户经历或模型密钥。

建议指标：

- 首 Token 延迟和总生成耗时；
- SSE 中断率；
- Tool 参数解析失败率；
- proposal 进入审批、同意、拒绝和失效率；
- 字段 revision 冲突率；
- 自动续跑失败率；
- 延迟 Tool Result 补传率和最终 consumed 比例；
- 孤儿会话和孤儿运行数量；
- 按供应商和模型聚合的错误码。

日志只记录 ID、状态、耗时、模型名和稳定错误码。默认不得记录完整用户消息、经历内容、
Tool 建议值、系统提示词或 API Key。

## 10. P2：上下文窗口与超长会话

一个字段会话允许多轮讨论，但模型上下文有上限。后续需要明确：

- 最大轮数和最大输入长度；
- Token 预算估算；
- 只选取完整成功消息；
- 历史裁剪顺序；
- 是否建立可验证的会话摘要；
- 摘要生成失败时的确定性降级；
- Tool Call 与 Tool Result 不能被拆开裁剪；
- 最新数据库上下文始终优先保留。

## 11. P2：取消、超时与资源释放

后续需要区分：

- 用户停止生成；
- 页面离开；
- 浏览器断开；
- 服务端超时；
- 供应商超时；
- worker lease 过期。

应明确每种情况是否取消供应商请求、是否保存部分消息、是否结束会话、是否保留 Tool
Result，以及连接和数据库 Session 的释放时点。

## 12. P2：历史会话与恢复产品设计

首期历史只入库、不展示、不恢复。若后续开放历史，需要单独设计：

- 只读历史与可继续会话的区别；
- 是否允许恢复 ended 会话；
- 恢复后的字段上下文与旧消息冲突；
- 已删除或已归档 subject 的展示；
- 历史中的提案值、审批结果和隐私清理；
- 新会话是否允许引用历史摘要。

在该设计完成前，不得直接增加“继续历史会话”按钮。

## 13. 建议实施顺序

1. 持久化 continuation job/outbox 和崩溃恢复。
2. SSE 持久化事件 ID、重连和重放。
3. 供应商 Tool Call 契约测试与错误分类。
4. 重试、退避、熔断和备用模型策略。
5. 多标签页同步和审批主动失效。
6. 一致性审计、指标和隐私安全日志。
7. 上下文窗口、取消语义和超长会话处理。
8. 历史会话产品设计。

## 14. 后续完成定义

失败处理优化不能只以“增加 try/except”视为完成。至少需要：

- 进程在审批事务后任意时点退出，重启后不会重复字段覆盖；
- 未完成续跑能被确定恢复或确定降级；
- SSE 重连不会丢失或重复应用审批事件；
- 所有支持的模型供应商通过 Tool Call 分片契约测试；
- 可重试和不可重试错误具有稳定分类；
- 多标签页写入不会绕过字段 revision；
- 一致性审计能够发现所有已知非法状态；
- 监控可以回答 Tool Result 是否最终被模型消费；
- 日志和指标不泄露用户经历正文或密钥。
