# ADR-0001：二次开发产品范围裁剪

状态：已接受  
日期：2026-09-05

## 背景

本项目基于上游 Resume Matcher 二次开发。上游包含申请追踪、主简历向导、求职信、外联消息、面试准备、复杂模板和多语言配置等功能；它们不都服务当前要建设的证据驱动 Agent 产品。

## 决策

当前产品只把以下链路视为主线：

`资料/经历 → 事实与 Evidence → JD 导入与澄清 → 证据检索 → 岗位简历生成 → 来源核验 → 用户审核 → 导出`

Application Tracker 和 Resume Wizard 已从运行入口、专属页面、API、组件和测试移除。Cover Letter、Outreach 和 Cover Letter PDF 已停止对外服务，端点返回 `410 Gone`；Resume Builder 不再显示这些 Tab。Interview Prep 后端暂留，仅作为历史数据和 API 兼容层，不得新增功能。

## 理由

- 证据和事实版本是产品差异化核心，其他文案类型会分散数据、评估和交互设计。
- 删除重复入口能降低维护成本，避免同一份资料存在多套状态机。
- 先退出运行入口，再处理历史数据，可以降低数据损坏风险。
- 旧代码可以通过 Git 历史追溯，不需要为了“保留上游”继续维护其产品语义。

## 后果

- 任何新功能必须说明它如何服务主线，否则进入暂停或拒绝清单。
- 历史 `Application` 表、旧简历内容字段和部分数据库方法暂时保留；它们不能被新代码依赖。
- 设置页、响应 Schema 和数据库字段仍有清理工作；删除前必须完成数据盘点、一次性迁移和恢复演练。
- 上游历史文档不作为当前实现依据，当前入口以 `docs/README.md` 和 `docs/roadmap/` 为准。

## 重新引入条件

只有在真实用户研究确认需求、定义独立数据归属、权限模型、失败处理和质量评估后，才允许以新的模块或 Skill 重新引入被裁剪能力。恢复旧页面或旧端点不算完成重新设计。
